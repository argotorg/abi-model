# bug002: enum tag of a `memory<DynArray<t>>` field signs as the enclosing method's name

| | |
|---|---|
| Found by | abi-model differential tests (`nix run .#diff`, fixed cases) |
| Solcore | `a7b7afb0638e50895008d778a167afd0e50a2c86` |
| Area | type-class resolution of `SigString`, enum constructor tags |
| Files | [`case24.sol`](case24.sol), [`case24.json`](case24.json) |
| Status | open, not reported |

## Summary

A derived enum's constructor tag is `keccak256("Name(" + sigStr(rep) + ")")`
(`DeriveGeneric.tagE`). For a constructor with a `memory<DynArray<uint256>>`
field, the model expects `keccak256("B(uint256[])")`, the signature the
dispatcher uses for `calldata<array<uint256>>`. Solcore instead hashes
**`B(case0)`**, where `case0` is the name of the method that does the encoding.

`std/dispatch.sol` has no `SigString` instance for `memory<DynArray<t>>` (only
for `calldata<array<t>>`). Rather than rejecting the program, Solcore selects
the fallback

```solidity
default impl<a, rep> SigString<a> where a: Generic<rep>, rep: SigString {
  function sigStr(x:Proxy<a>) returns (string) {
    return SigString.sigStr( @rep );
  }
}
```

although `memory<DynArray<uint256>>` has no `Generic` instance. Its `rep` is
resolved to the dispatch name type of the enclosing method. In the specialised
program (`sol-core --dump-spec`):

```
function SigString_sigStr$a$memoryLDynArrayLuint256JJ (x : Proxy(memory(DynArray(uint256)))) -> string {
   return SigString_sigStr$DispatchNameTy_AbiModelDiff_case0<...>(Proxy.Proxy<Proxy(DispatchNameTy_AbiModelDiff_case0)>);
}
```

and `keccak256("B(case0)")` is exactly the tag in the return data.

## Reproduction

[`case24.sol`](case24.sol) is the contract generated by `abidiff` for the model
case `enum {A word | B (array word) | C word} = B [8, 9]`:

```solidity
enum E_9a6aa62bc87d276e { A(uint256), B(memory<DynArray<uint256>>), C(uint256) }
...
let v : E_9a6aa62bc87d276e = E_9a6aa62bc87d276e.B([8, 9]);
return abi_encode(v);
```

[`case24.json`](case24.json) is the matching `testrunner` file, whose expected
return data is the model's prediction. Return data, word by word (`abi_encode`
returns `bytes`, so words 0 and 1 are the `bytes` offset and length):

| word | role               | expected (model)                    | actual (Solcore)                    |
|------|--------------------|-------------------------------------|-------------------------------------|
| 0    | bytes offset       | `0x20`                              | `0x20`                              |
| 1    | bytes length       | `0xc0`                              | `0xc0`                              |
| 2    | enum offset        | `0x20`                              | `0x20`                              |
| 3    | tag                | `0x38d4…d082` = keccak `B(uint256[])` | **`0x83f6…cfd9`** = keccak `B(case0)` |
| 4    | array offset       | `0x40`                              | `0x40`                              |
| 5–7  | length, data       | `2, 8, 9`                           | `2, 8, 9`                           |

Only the tag differs; the layout is as the model predicts.

The tag follows the method name, not the contract contents:

- renaming `case0` to `foo` makes the tag `keccak256("B(foo)")`;
- adding an unrelated method before `case0` does not change it;
- `--type-class-resolution legacy` and `tabled` behave the same.

To rerun the case with the testrunner, put both files under Solcore's
`test/examples/dispatch/` (or rerun `nix run .#diff` against `a7b7afb`; the
case is `case24` of `AbiDiff/Cases.lean`).

## Impact

The same enum gets a different tag in every method that encodes it, so a value
encoded by one method (or contract) is decoded as the wrong constructor, or as
the default last constructor, by another. Enums whose fields are all `uint256`,
`bool`, `()`, pairs, `sum`s or other enums of these are not affected (the other
enum cases of `AbiDiff/Cases.lean` agree with the model).

## Expected

Either a `SigString<memory<DynArray<t>>>` instance signing as `t[]` (matching
`calldata<array<t>>`, and the model), or a compile error for the missing
instance. A `default impl` should not be selected when its `Generic<rep>`
constraint has no solution.
